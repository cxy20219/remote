# SSH 隧道直通流程测试用例

## 1. 测试目的

验证 GoRemote SSH 隧道直通功能的正确性和稳定性，覆盖正常流程、边界条件和异常情况。

**核心功能**：通过 WebSocket 隧道实现公网 SSH 连接内网服务器

```
外部用户 ──▶ [服务端:公网端口] ──▶ [WebSocket隧道] ──▶ [Agent:本地端口]
            (端口映射)              (数据透传)          (内网服务)
```

## 2. 测试环境

### 2.1 部署架构

| 组件 | 地址 | 角色 |
|------|------|------|
| Server | YOUR_SERVER:8080 | 公网服务端 |
| Agent | 192.168.66.42 | 内网客户端 |
| 内网 SSH | 192.168.66.42:22 | 目标服务 |

### 2.2 配置参数

| 参数 | 值 |
|------|-----|
| 隧道端口范围 | 10000-20000 |
| 每客户端最大隧道数 | 10 |
| 默认 local_addr | 127.0.0.1 |
| 心跳间隔 | 30s |
| 心跳超时 | 90s |

### 2.3 前置条件

- Server 和 Agent 均已部署并运行
- Agent 已成功注册到 Server
- 可以通过 HTTP API 创建隧道

## 6. 附录

### 6.1 API 快速参考

| 方法 | 路径 | 描述 |
|------|------|------|
| GET | /health | 健康检查 |
| GET | /api/clients | 在线客户端列表 |
| GET | /api/clients/:id | 客户端详情 |
| GET | /api/clients/:client_id/tunnels | 客户端隧道列表 |
| POST | /api/tunnels | 创建端口映射 |
| GET | /api/tunnels | 所有隧道列表 |
| GET | /api/tunnels/:tunnel_id | 隧道详情 |
| DELETE | /api/tunnels/:tunnel_id | 删除端口映射 |

### 6.2 WebSocket 消息类型

| Type | 方向 | 描述 |
|------|------|------|
| register | C→S | 客户端注册 |
| register_ok | S→C | 注册成功 |
| register_fail | S→C | 注册失败 |
| ping | C→S | 心跳请求 |
| pong | S→C | 心跳响应 |
| tunnel_open | C→S | 申请创建隧道 |
| tunnel_open_ack | S→C | 隧道创建确认 |
| tunnel_close | C↔S | 关闭隧道 |
| tunnel_data | C↔S | 隧道数据（双向） |
| tunnel_error | S→C | 隧道错误通知 |

### 6.3 测试注意事项

1. **PowerShell JSON 处理**：使用 `Invoke-RestMethod` 配合 `ConvertTo-Json` 时需注意变量展开，必要时使用字符串直接量
2. **端口耗尽测试**：端口范围 10000-20000 共 10000 个端口，实际耗尽耗时长，可通过代码审查验证逻辑
3. **心跳超时测试**：超时时间 90 秒，实际测试耗时长，可通过代码审查验证逻辑
4. **异常关闭测试**：测试后需重启 Agent 恢复服务
